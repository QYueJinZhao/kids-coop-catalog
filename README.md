# 儿童同屏合作游戏分类库（kids-coop-catalog）

把已有调研里的 **224 条**创意 / 冒险 / 第三批条目，收进一套可筛选、可搜索、可追溯的分类站点。

- 站点入口：[`index.html`](index.html)（单文件，`file://` 双击即开，无外网依赖、无服务端、无第三方库）
- 数据：[`data/catalog.json`](data/catalog.json)（224 条，每条带稳定 id）
- 构建：[`scripts/build.mjs`](scripts/build.mjs)（数据 → 单文件页面）
- 冒烟：[`scripts/smoke.mjs`](scripts/smoke.mjs) + [`smoke-report.json`](smoke-report.json)（真实 Chrome，25/25 通过）

> 证据边界：全库 **E2（真人试玩）= 0**。4 条有 HTML 原型 + 合成代理实测（E1），其余 220 条是 **E0 纸面推理**。
> 「站点能开、冒烟能过、数据可追溯」不等于「分类体系已被验证」。

## 1. 分类骨架从哪来

参考文章《500 款开源游戏 · 按玩法 + 引擎双轴分类》（SuperStarPark，公众号 NO.016）的**组织方法**，不复制它的条目与文案。文章实际讲的是：

| 文章的做法 | 具体内容 |
|---|---|
| 双轴 | 「玩法」×「引擎/技术栈」两个切面看同一批游戏 |
| 九个板块（按载体/形态分） | AI 生成 12 · 浏览器 144（13 类）· 原生 174（13 类）· 移动 24（Android 12 / iOS 12）· 聊天机器人 1 · 仅源码 13 · 框架/引擎/库 68 · 地图/插件/工具 21 · 按引擎 24 |
| 浏览器 13 类 | 棋牌桌游 10、街机 60、音乐节奏 1、FPS 3、RPG 3、MMO 2、策略 6、竞速 2、沙盒 4、解谜 38、点击放置 1、点击解谜 1、其他 13 |
| 原生 13 类 | 动作 4、街机 19、音乐节奏 7、FPS 17、MMO 7、RPG 18、平台跳跃 16、解谜/卡牌/桌游 14、竞速 4、编程 1、沙盒 15、模拟 4、策略 48 |
| 读者画像 | 纯玩家 / 开发萌新 / 独立开发者 / Vibe Coder，按画像给阅读路线 |
| 单条结构 | 名称 + 类型标签 + 一句话玩法 + 策划亮点 + 仓库链接 +「新增」标记 |
| 引擎轴 | Godot / Unity / Phaser / Bevy / Three.js / PICO-8 / GameMaker 等 |
| 分级 | 封面 `GRADE S` 是文章自身的徽章；正文没有对单款游戏逐条打 S/A/B |

文章可核实的关键结论只有一句：它按「玩法 + 引擎」双轴、按载体分板块来组织一份 500 条的开源游戏清单。**它没有提出一套可复用的分级标准**，也没有给每条游戏打分。

### 映射到本库

| 文章骨架 | 本库落地 | 说明 |
|---|---|---|
| 玩法轴 | **玩法族 23 类**（F01–F10 / S01–S08 / G1–G5） | 直接沿用三个原池的机制家族，不另造一套；原文 13 类太粗，会抹掉「4P 分工」这类关键差异 |
| 引擎 / 技术栈轴 | **载体形态**：HTML 灰盒可验 / 需引擎或定制原型 / HTML 原型已验证 | 本库全是设计阶段条目，没有真实引擎工程 |
| 九大板块（载体） | **平台**：本地同屏热座（键鼠 / 手柄） | 全部条目都按同屏合作设计，没有联机条目 |
| 读者画像 | 筛选器 + 卡片元数据 | 家长/老师按年龄、时长、门槛筛；开发者按玩法族、证据等级筛 |
| 单条结构 | 一句话玩法 + 核心动词 + 一句判据 + 来源指针 | 判据必须能从原池定义解释，避免「看标题归类」 |
| `GRADE` 徽章 | **证据等级 E0 / E1 / E2** | 只按「有什么可核验的证据」分级，不按「好不好玩」评分 |
| 许可说明 | 代码 MIT；数据与文本 CC BY 4.0 | 见文末 |

## 2. 八个必需维度 + 两个附加维度

站点可筛、可搜（标题 / 英文名 / 玩法 / 核心动词 / 编号 / 正文要点），编号精确搜索优先。

| # | 维度 | 取值 | 来源 / 判据 |
|---|---|---|---|
| 1 | 玩法族 | 23 类：F01–F10（创意池 10 族，各 12 条）、S01–S08（冒险池 8 结构，各 8 条）、G1–G5（第三批 5 母题组，8/8/12/8/4 条） | 原池机制家族定义，未重分类 |
| 2 | 玩家人数 | 1P 120 · 2P 121 · 3P 40 · 4P 168（一条可命中多档） | 原池 `p1/p2/p4` 只把「成立」计入；`需验证` 写进备注 |
| 3 | 目标年龄 | 5–9 岁（96 条）/ 6–10 岁（128 条） | **推断**：由上手门槛反推，非逐条验证；原池池级年龄带为「核心 6–10 岁」 |
| 4 | 单局时长 | ≤1 分钟 1 · 1–3 分钟 121 · 3–5 分钟 102 | A01/A25/A41/B17 为实测；其余按「30 秒闭环 × N 次」或「3 段 × 60–70 秒」推断 |
| 5 | 上手门槛 | 低 96 / 中 128 | **推断**：按玩法族的 `kidsFit` 映射，非儿童测试 |
| 6 | 情绪基调 | 轻快 114 · 紧张 44 · 温暖 30 · 滑稽 23 · 惊奇 13 | **关键词规则推导**（笑点/掉落/照顾/亮晶晶…），不是情感测量；未命中记「轻快」 |
| 7 | 平台 / 载体 | 目标：本地同屏热座；形态：HTML 灰盒可验 207 · 需引擎 17（4 条原型另有 E1 记录） | 原池 `feas` 与 `gate.html` 映射 |
| 8 | 价格带 | 低价买断 ≤¥50：133 · 中价 ¥50–100：85 · 高价 >¥100：6 | **推断**：五成本桶加权，无商业验证；第三批无成本字段，按规模推断 |
| 9 | 证据等级 | E0 220 / E1 4 / E2 0 | E1 = HTML 原型 + 合成代理实测；E0 = 纸面推理 |
| 10 | 适配分 | 1–5（原池 `fit`），≥4 共 174 条 | 原池自评分，不是市场分 |

## 3. 条目字段表

| 字段 | 类型 | 含义 | 可追溯性 |
|---|---|---|---|
| `id` | string | 稳定编号：`I001`–`I120`（创意池）、`A01`–`A64`（冒险池）、`B01`–`B40`（第三批） | 与源 JSON 的 `id` 一一对应 |
| `title` / `titleEn` | string | 中文名 / 英文名 | 原文 |
| `pool` / `poolLabel` | string | P1 创意池 / P2 冒险池 / P3 第三批 | 原文文件 |
| `playKey` / `play` | string | 玩法族编号与名称（如 `S01 共同搬运`） | 原池 `family` / `structure` / `group` |
| `playDesc` | string | 该玩法族的定义 | 原池家族说明 |
| `oneLiner` | string | 一句话玩法（原文核心循环） | 原池 `loop` |
| `coreVerb` | string | 核心动词（吸、抬、分、守…） | 原池 `verb` |
| `players` | object | `modes[]` 成立人数 + `note` 原文人数备注 | 原池 `p1/p2/p4`、`gate.fourth` |
| `age` | object | `band` 目标年龄 + `basis` 推断依据 | 池级年龄带 + 门槛映射 |
| `session` | object | `band` 时长档 + `seconds` 实测秒数（仅 4 条）+ `basis` | 原型 REPORT / 结构推断 |
| `onboarding` | enum | 低 / 中 / 高 | 原池 `kidsFit` 映射 |
| `mood` | enum | 滑稽 / 温暖 / 惊奇 / 紧张 / 轻快 | 关键词规则 |
| `platform` | object | `target` 目标平台 + `tech` 实现形态 + `basis` | 原池 `feas` / `gate.html` |
| `price` | object | `band` 价格带 + `basis` | 成本桶加权 |
| `evidence` | object | `level` E0/E1/E2 + `label` + `note` | 有无原型/真人数据 |
| `fit` | number | 适配分 1–5 | 原池 `fit` |
| `why` | string | 一句分类判据（含玩法族定义与人数依据） | 由原池定义组装，非人工拍脑袋 |
| `detail` | object | 原文要点（循环、分工、风险、HTML 证伪方式等，随池不同） | 原文选摘 |
| `risk` / `lineage` / `dedup` | string | 风险 / 机制谱系 / 去重状态 | 原文 |
| `source` | object | 源文件 + JSON 指针（如 `#/entries/0`）+ 原池方法说明 | 可直接回查 |
| `prototype` | object/null | 4 条 E1 条目的形态、实测、冒烟、结论、证据边界 | 原型 REPORT / FINAL-VERDICT |

## 5. 如何新增一条

**A. 从原池新增（推荐，保留追溯）**

1. 在只读源目录的 `ideas.json` / `adventures.json` / `adventures3.json` 里按原 schema 增加条目。
2. 重跑入库：
   ```bash
   node scripts/ingest.mjs <kids-fantasy/data 目录>
   ```
3. 构建 + 冒烟（见下）。

**B. 直接手工新增到 `data/catalog.json`**

1. 在 `entries` 末尾复制一条结构相同的对象。
2. 必填：`id`（前缀不复用）、`title`、`pool`、`playKey`（必须在 `meta.playDefs` 里）、`oneLiner`、`coreVerb`、`players.modes`（至少一档）、`age`、`session`、`onboarding`、`mood`、`platform`、`price`、`evidence`、`fit`、`why`、`source`。
3. `node scripts/build.mjs` 会校验重复 id、缺字段、非法枚举、玩法族不存在、适配分越界；不通过直接失败，不会生成半成品。
4. `node scripts/smoke.mjs` 真跑浏览器；新增条目后条目数断言会自动跟着 `catalog.json` 走。
5. 同步更新 `meta.entryCount` 与 README 的统计数字。

## 7. 证据不足 / 不能拿它当结论的地方

1. **年龄、门槛、情绪、价格带都是推断**，依据是原池家族适配判断、文本关键词、成本桶加权；没有任何儿童测试或市场数据。
2. **时长只有 4 条实测**（合成代理，不是真人）；其余按结构估算。
3. **人数只按原文标注**：冒险池大量条目 `2P 需验证`、`1P 不成立`；本库不额外判定 3P 是否成立。
4. **E2 = 0**：没有真人试玩，没有「孩子看得懂 / 愿意重玩 / 会笑」的证据。
5. **外部商业同类未接入**：为避免引用未核实事实，本库不收录市面对照条目；机制谱系只在原文 `lineage` 字段里出现。
6. **分类体系未验证**：没有做检索实验（例如让家长按维度找游戏），因此「能筛」只是功能可用，不是分类有效性。
7. **「第三批」价格带无成本字段**，按同池规模推断，最弱。
8. **玩法族 23 类与原池绑定**：适合内部研发检索，不适合直接对外做市场分类；跨池比较需要再做一层归并。
