# 儿童同屏合作游戏分类库（kids-coop-catalog）

把已有调研里的 **224 条**创意 / 冒险 / 第三批条目，加上 **16 款 Steam 在售同类游戏**，收进一套可筛选、可搜索、可追溯的分类站点。

- 站点入口：[`index.html`](index.html)（单文件，`file://` 双击即开，无外网依赖、无服务端、无第三方库）
- 数据：[`data/catalog.json`](data/catalog.json)（自有 224 条）、[`data/market.json`](data/market.json)（市面对照 16 款）
- 构建：[`scripts/build.mjs`](scripts/build.mjs)（两个数据文件 → 单文件页面）
- 冒烟：[`scripts/smoke.mjs`](scripts/smoke.mjs) + [`smoke-report.json`](smoke-report.json)（真实 Chrome，43/43 通过）

> 证据边界：全库 **E2（真人试玩）= 0**。4 条有 HTML 原型 + 合成代理实测（E1），220 条是 **E0 纸面推理**，16 款市面对照是 **E3 外部可核实事实**（商店页 / SteamSpy，不是试玩证据）。
> 「站点能开、冒烟能过、数据可追溯」不等于「分类体系已被验证」。

## 1. 分类骨架从哪来

参考文章《500 款开源游戏 · 按玩法 + 引擎双轴分类》（SuperStarPark，公众号 NO.016）的**组织方法**，不复制它的条目与文案。文章实际讲的是：

| 文章的做法 | 具体内容 |
|---|---|
| 双轴 | 「玩法」×「引擎/技术栈」两个切面看同一批游戏 |
| 九个板块（按载体/形态分） | AI 生成 12 · 浏览器 144（13 类）· 原生 174（13 类）· 移动 24（Android 12 / iOS 12）· 聊天机器人 1 · 仅源码 13 · 框架/引擎/库 68 · 地图/插件/工具 21 · 按引擎 24 |
| 浏览器 13 类 | 棋牌桌游 10、街机 60、音乐节奏 1、FPS 3、RPG 3、MMO 2、策略 6、竞速 2、沙盒 4、解谜 38、点击放置 1、点击解谜 1、其他 13 |
| 原生 13 类 | 动作 4、街机 19、音乐节奏 7、FPS 17、MMO 7、RPG 18、平台跳跃 16、解谜/卡牌/桌游 14、竞速 4、编程 1、沙盒 15、模拟 4、策略 48 |
| 读者画像 | 纯玩家 / 开发萌新 / 独立开发者 / Vibe Coder，按画像给阅读路线 |
| 单条结构 | 名称 + 类型标签 + 一句话玩法 + 策划亮点 + 仓库链接 +「新增」标记 |
| 引擎轴 | Godot / Unity / Phaser / Bevy / Three.js / PICO-8 / GameMaker 等 |
| 分级 | 封面 `GRADE S` 是文章自身的徽章；正文没有对单款游戏逐条打 S/A/B |

文章可核实的关键结论只有一句：它按「玩法 + 引擎」双轴、按载体分板块来组织一份 500 条的开源游戏清单。**它没有提出一套可复用的分级标准**，也没有给每条游戏打分。

### 映射到本库

| 文章骨架 | 本库落地 | 说明 |
|---|---|---|
| 玩法轴 | **玩法族 23 类**（F01–F10 / S01–S08 / G1–G5） | 直接沿用三个原池的机制家族，不另造一套；原文 13 类太粗，会抹掉「4P 分工」这类关键差异 |
| 引擎 / 技术栈轴 | **载体形态**：HTML 灰盒可验 / 需引擎或定制原型 / HTML 原型已验证 | 本库全是设计阶段条目，没有真实引擎工程 |
| 九大板块（载体） | **平台**：本地同屏热座（键鼠 / 手柄） | 全部条目都按同屏合作设计，没有联机条目 |
| 读者画像 | 筛选器 + 卡片元数据 | 家长/老师按年龄、时长、门槛筛；开发者按玩法族、证据等级筛 |

| `GRADE` 徽章 | **证据等级 E0 / E1 / E2 / E3** | 只按「有什么可核验的证据」分级，不按「好不好玩」评分 |
| 许可说明 | 代码 MIT；数据与文本 CC BY 4.0 | 见文末 |

## 2. 八个必需维度 + 两个附加维度

站点可筛、可搜（标题 / 英文名 / 玩法 / 核心动词 / 编号 / 正文要点），编号精确搜索优先。

| # | 维度 | 取值 | 来源 / 判据 |
|---|---|---|---|
| 1 | 玩法族 | 23 类：F01–F10（创意池 10 族，各 12 条）、S01–S08（冒险池 8 结构，各 8 条）、G1–G5（第三批 5 母题组，8/8/12/8/4 条） | 原池机制家族定义，未重分类 |

| 3 | 目标年龄 | 5–9 岁（96 条）/ 6–10 岁（128 条） | **推断**：由上手门槛反推，非逐条验证；原池池级年龄带为「核心 6–10 岁」 |
| 4 | 单局时长 | ≤1 分钟 1 · 1–3 分钟 121 · 3–5 分钟 102 | A01/A25/A41/B17 为实测；其余按「30 秒闭环 × N 次」或「3 段 × 60–70 秒」推断 |
| 5 | 上手门槛 | 低 96 / 中 128 | **推断**：按玩法族的 `kidsFit` 映射，非儿童测试 |
| 6 | 情绪基调 | 轻快 114 · 紧张 44 · 温暖 30 · 滑稽 23 · 惊奇 13 | **关键词规则推导**（笑点/掉落/照顾/亮晶晶…），不是情感测量；未命中记「轻快」 |
| 7 | 平台 / 载体 | 目标：本地同屏热座；形态：HTML 灰盒可验 207 · 需引擎 17（4 条原型另有 E1 记录） | 原池 `feas` 与 `gate.html` 映射 |
| 8 | 价格带 | 低价买断 ≤¥50：133 · 中价 ¥50–100：85 · 高价 >¥100：6 | **推断**：五成本桶加权，无商业验证；第三批无成本字段，按规模推断 |
| 9 | 证据等级 | E0 220 / E1 4 / E2 0 / E3 16 | E1 = HTML 原型 + 合成代理实测；E0 = 纸面推理；E3 = 外部可核实事实（市面 16 款） |
| 10 | 适配分 | 1–5（原池 `fit`），≥4 共 174 条 | 原池自评分，不是市场分；市面条目一律 `null`，不做评分 |

## 4. 证据等级 E0 / E1 / E2 / E3

| 等级 | 含义 | 本库现状 | 能证明什么 | 不能证明什么 |
|---|---|---|---|---|
| **E0** | 纸面推理 | 220 条自有条目 | 设计意图、机制结构、分类归属 | 能不能做出来、孩子愿不愿意玩 |
| **E1** | HTML 原型 + 合成代理实测 | 4 条（A01 / A25 / A41 / B17） | 该形态能在浏览器跑通，合成代理可完成闭环并测时长 | 真人（尤其儿童）是否觉得好玩、看得懂 |
| **E2** | 真人试玩 | **0 条** | — | — |
| **E3** | 外部可核实事实 | 16 款 Steam 在售游戏 | 这款游戏真实存在、商店页这样写、采样时点的价格与评测数 | 儿童适配、玩法好坏、是否值得买 |

等级按「证据可核验程度」分类，**不是质量排名**。E3 不比 E1 高：E3 证明的是「市面事实」，E1 证明的是「我们自己的形态跑通了」，两者不能互相替代。全库没有任何 E2，所以「孩子会喜欢」始终是未验证假设。

## 5. 市面对照层（`origin: market`）

条目来源只有两种：`own`（自有创意 224 条）与 `market`（市面对照 16 款）。两者共用同一套字段和同一个玩法族轴，但市面条目**不做适配分、不做「谁更好」评分**。

数据只来自已核实的采样文件 `research/kids-fantasy/data/steam-demand-2026-11-04.json`（采样时间 `2026-11-04T07:18:09Z`；方法：Steam storesearch + appdetails + SteamSpy appdetails + 商店页评测摘要 + 社区近期评测抽样），不额外抓取、不推断补齐。

### 5.1 市面条目字段边界

| 字段 | 写法 |
|---|---|
| 名称 / Steam 链接 | 商店页名称；`https://store.steampowered.com/app/<appid>/` |
| 官方支持人数 | **照抄官方原文**（如 `1, 2 or 4 players`）；商店页没写就写「未获取」 |
| `players.modes` | 只从官方原文明确语句解析出的可筛档位（1P–4P）；解析不出就留空 |
| 初始价 / 采样价 / 折扣 | 采样文件 `basePriceUSD` / `priceAtSampleUSD` / `discountPctAtSample`，USD |
| 评测数 / 好评率 | SteamSpy 全语言合计 + 商店页近期评价标签；口径可能不同于商店页英文子集 |
| 玩法族映射 | `playKeys[]`，可多族并列；映射不到写 `[]`，单列「未归类」 |
| 机制谱系关联 | `lineage` + `relatedOwn`：同族自有条目编号并列；**不是**原文里的直接谱系引用 |
| 采样时间 | `sampledAt`，所有价格 / 评测 / 在线数都只代表这一时点 |
| 年龄 / 时长 / 门槛 / 情绪 / 价格带 | 一律「未获取」——商店页没有这些标注，不推断 |

> **人数只认官方文本**。Steam 标签、类目、`maxPlayers` 字段都不能替代原文；抓到的若不是人数字句（例如系统需求），按「未获取」处理。
> **价格与评测数是采样时点值**，不是历史最低价、不是峰值、不是销量。

### 5.2 16 款的映射结果

- **覆盖 12 / 23 个玩法族**：
  - F01 抓与搬 5 款 · F02 搭与塌 6 款 · F05 煮与变 3 款 · F06 收与分 1 款 · F09 拍与仿 1 款 · F10 滑与路 3 款 · F03 抛与落 1 款
  - S01 共同搬运 2 款 · S02 视野分工 1 款 · S03 角色互补 3 款 · S04 旅途资源 1 款 · S08 接力传递 3 款
- **未覆盖 11 族**：F04、F07、F08、S05、S06、S07、G1、G2、G3、G4、G5
- **未归类 1 款**：`M10 Castle Crashers®` —— 核心是横版格斗 / 竞技场对战，本库 23 族里没有「战斗 / 对抗」族，不硬塞

映射原则：
1. 一款可映射到多族时**全部列出**，并在 `why` 写一句判据（机制动作对得上，不是因为题材像）。
2. 映射不到就留空 `playKeys`，进「未归类」，不为了凑满而硬塞。
3. 映射是**编者判据**，不代表厂商或发行商分类。

### 5.3 对照视图怎么读

1. 点顶部「玩法族对照」页签，切换为按族并列的视图。
2. 每行一个玩法族：**左栏「本库自有」**，**右栏「市面对照（Steam 采样）」**。
3. 右栏有游戏 = 这 16 款里已经有人做到这个方向；标「本样本内未见对照」= 这 16 款里没有映射到该族，**不等于市场空白**。
4. 「未归类（市面）」单独一行，放在 23 族之后。
5. 点击任意小卡打开详情；搜索与玩法族筛选在对照视图里生效，来源筛选与人数/价格下拉只作用于列表视图。
6. 视图只回答「有没有人做」，**不排序、不评分、不判断谁更好**。

## 7. 如何新增一条

**A. 从原池新增（推荐，保留追溯）**

1. 在只读源目录的 `ideas.json` / `adventures.json` / `adventures3.json` 里按原 schema 增加条目。
2. 重跑入库：
   ```bash
   node scripts/ingest.mjs <kids-fantasy/data 目录>
   ```
3. 构建 + 冒烟（见下）。

**B. 直接手工新增到 `data/catalog.json`**

1. 在 `entries` 末尾复制一条结构相同的对象。
2. 必填：`id`（前缀不复用）、`title`、`pool`、`playKey`（必须在 `meta.playDefs` 里）、`oneLiner`、`coreVerb`、`players.modes`（至少一档）、`age`、`session`、`onboarding`、`mood`、`platform`、`price`、`evidence`、`fit`、`why`、`source`。
3. `node scripts/build.mjs` 会校验重复 id、缺字段、非法枚举、玩法族不存在、适配分越界；不通过直接失败，不会生成半成品。
4. `node scripts/smoke.mjs` 真跑浏览器；新增条目后条目数断言会自动跟着 `catalog.json` + `market.json` 走。
5. 同步更新 `meta.entryCount` 与 README 的统计数字。

**C. 新增市面对照条目**

1. 先在只读采样文件里确认该游戏已被核实（名称、appid、商店页人数原文、价格、评测数）。
2. 在 `scripts/ingest-market.mjs` 的 `MAPPING` 表里按 appid 增加一条：`keys`（玩法族，可为空）、`why`（一句映射判据）、`modes`（只写官方原文能确认的档位）、`modesNote`。
3. 重跑：
   ```bash
   node scripts/ingest-market.mjs <steam-demand-2026-11-04.json 路径>
   node scripts/build.mjs
   ```
4. 不接受手工补齐：查不到的字段写「未获取」，映射不到就进「未归类」。

## 8. 构建与冒烟

```bash
# 0) 仅当源数据更新时：重建自有条目 / 市面条目（源目录只读）
node scripts/ingest.mjs <kids-fantasy/data 目录>
```

## 9. 证据不足 / 不能拿它当结论的地方

1. **年龄、门槛、情绪、价格带都是推断**，依据是原池家族适配判断、文本关键词、成本桶加权；没有任何儿童测试或市场数据。
2. **时长只有 4 条实测**（合成代理，不是真人）；其余按结构估算。
3. **人数只按原文标注**：冒险池大量条目 `2P 需验证`、`1P 不成立`；本库不额外判定 3P 是否成立。
4. **E2 = 0**：没有真人试玩，没有「孩子看得懂 / 愿意重玩 / 会笑」的证据。
5. **市面对照只覆盖 16 款、12/23 族**：这是采样样本，不是 Steam 全量；「本样本内未见对照」不等于市场空白，也不代表该方向没人做。选样偏差未测量。
6. **市面字段只到采样时点**：价格、评测数、在线人数都是 `2026-11-04T07:18Z` 前后的一次快照；不是历史最低价、不是峰值、不是销量。评测数为 SteamSpy 全语言合计，与商店页英文子集口径可能不同（Overcooked! 2 的初始价 48.49 USD 已按源文件 caveat 标注异常）。
7. **市面人数只认官方原文**：原文没写就写「未获取」，不用标签、类目或 `maxPlayers` 反推；因此多数市面条目没有可筛人数档，也无法做「按人数对照」。
8. **玩法族映射是编者判据**：不是厂商分类，也不保证穷尽；一款游戏可映射多族，本库列全部并写判据，但不同编者可能给出不同映射。
9. **不做优劣评分**：对照视图只回答「这 16 款里有没有人做这个方向」，不判断「谁更好」「哪个更值得做」。
10. **分类体系未验证**：没有做检索实验（例如让家长按维度找游戏），因此「能筛」只是功能可用，不是分类有效性。
11. **「第三批」价格带无成本字段**，按同池规模推断，最弱。
12. **玩法族 23 类与原池绑定**：适合内部研发检索，不适合直接对外做市场分类；跨池比较需要再做一层归并。
